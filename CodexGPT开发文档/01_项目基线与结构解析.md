## 1. 项目身份与运行入口

| 项目项 | 当前事实 |
|---|---|
| 引擎 | Unity 2022.3.62f3 |
| 渲染 | Universal Render Pipeline 14.0.12 |
| 类型 | 3D TPS 原型，含单机 PVE 与独立 .NET UDP PVP 服务端 |
| 构建平台 | 当前 Build Settings 中为 Windows Standalone 场景序列 |

| 服务端 | `Server/ElementWarServer.csproj`，.NET 10，默认 UDP 7777、60Hz |

构建场景的实际流程是：

```text
GameStart（主菜单）
 ├─ 开始新游戏 → PVEGame（PVE：三角色、随从、敌人、投射物）
 └─ 在线 → PVPLobbyUI → PVPGame（PVP：一名本地角色、UDP 同步）
```

## 2. 代码结构与职责区分

项目自有运行/编辑器 C# 代码约 94 个文件：`Assets/Scripts` 85 个、`Server` 9 个。游戏自有脚本未定义独立 asmdef，默认落入 Unity 的 Assembly-CSharp/Assembly-CSharp-Editor；MagicaCloth 是插件自己的 asmdef，不能混为项目逻辑。

```text
Assets/Scripts/
├─ Base/          状态机宿主基类、敌人/玩家状态基类、Singleton、UIBase
├─ Player/        PVE 角色、输入/相机总控、武器、投射物、武器音频、六个状态
├─ Enemy/         ZombieEnemy 与 Idle/Move/Attack/Dead 状态
├─ Network/       PVP 客户端、UDP DTO/Socket、大厅、启动器、生成器
├─ FPS/           New Scene 的 Hunter/FPS 实验框架（与 PVE 主路径隔离）
├─ UI/            主菜单、提示/退出、Game Over、世界血条、TMP 交互
├─ Utils/         EffectPool、HeadAimTarget、StateMechaine
├─ Manager/       GameManager、UIManager、MonoManager
├─ Diagnostics/   F3 信息窗、地面/随从诊断
├─ Editor/        场景、NavMesh、字体、资源和 PVP 场景的 Editor Wizard
└─ Learn/         SimpleThirdPersonController 学习示例，不是主运行路径

Server/
├─ Program.cs              进程组合根与启动参数
├─ UdpGameServer.cs        UDP 收发、tick、路由、快照和可靠事件重发
├─ GameWorld.cs            零 IO 权威世界、移动、命中、bot、死亡与计分
├─ Messages.cs             服务端协议 DTO
├─ SnapshotBuilder.cs      全量快照构建
├─ ClientReplicator.cs     复制对象选择
├─ ReliableEventLedger.cs  ACK/重发账本
└─ Vec3.cs                 服务端轻量向量
```

### 2.1 PVE 主链路

```text
MyInputSystem（轮询）
  → PlayerController（输入、相机相对方向、角色切换、双相机、死亡接管）
  → PlayerModel + StateMechaine（角色状态、重力、Animator、血量、随从切换）
  → CharacterController / NavMeshAgent / Animator / Rig / Cinemachine
  → PlayerWeapon → PlayerWeaponBullet / EffectPool / WeaponAudio

EnemyBase + Zombie 状态机
  → NavMesh 追击/攻击 → PlayerModel.TakeDamage → 血条/死亡流程
```

- `PlayerController` 是当前 PVE 聚合点：输入、双 FreeLook、AimTarget、三角色切换、死亡接管都在其中，后续拆分需保留对外行为。
- `PlayerModel` 管理六个 PVE 状态：Idle、Move、Sprint、Slide、Hover、Aiming。代码移动采用 `LateUpdate`，但 Animator Root Motion 仍开启以使 Rig 生效。
- 荧与芙宁娜使用武器、投射物、火花/曳光/弹孔和 `WeaponAudio`；Hunter 的 `weapon`/IK 可为空，是当前设计基线。
- 敌人目前只有 `ZombieEnemy` 具体实现；攻击距离默认 1、伤害 10、冷却 1.5 秒。敌人攻击、受击和死亡由 `EnemyBase` 骨架统一管理。

### 2.2 PVP 链路与权威划分

```text
PVPLobbyUI → NetLobbyConfig → PVPGame / NetworkLauncher
  → NetClient（Input/Fire/ACK、快照、预测回滚、事件、远端实体）
     ├─ PvPMotor（本地预测与 Animator）
     ├─ PVPCameraRig / PVPHealthUI
     └─ RemoteAvatar（快照缓冲与插值）
UDP
  → UdpGameServer → GameWorld（权威模拟）
     → 全量 snapshot + 命中广播 + ACK 可靠生命周期事件
```

PVP 是与 PVE 刻意不同的运动模型：本地 `PlayerModel.disableStateMachine=true`，不用 PVE 的 CharacterController 位移或随从 NavMesh；`PvPMotor` 和 `GameWorld` 各自实现相同的简化数学。服务端默认数值：walk 2.2、jog 5、sprint 8、aim 2.5、gravity -15、jump 6.7、slide 0.8 秒、fire 0.15 秒、HP 100、伤害 25、复活 3 秒、胜利 5 分。PVP 的命中为服务端 hitscan 与历史帧回退，不应与 PVE 的 Rigidbody 子弹混淆。

## 3. 场景、资源与文件类型解析

### 3.1 场景分类

| 场景 | 角色 | 构建状态 | 变更方式 |
|---|---|---|---|

### 3.2 资源归属分类

| 类别 | 主要位置 | 处理原则 |
|---|---|---|
| 自有可执行逻辑 | `Assets/Scripts/`、`Server/` | 改前确认 PVE/PVP 边界与调用方。 |
| 自有游戏资源 | `Assets/Resource/` | 含 Animations、Effects、Models、Prefabs、字体、材质、纹理；引用变化需在 Editor 检查。 |
| Unity 配置 | `Assets/Settings/`、`Packages/`、`ProjectSettings/` | 包版本和渲染/输入配置属于项目基线，避免无关升级。 |
| 主场景资源 | `Assets/Scenes/` | 不手工编辑场景序列化文本；由 Unity 或 Editor Wizard 持久化。 |

## 4. 关键技术依赖与稳定点

| 技术 | 当前用途 | 变更注意 |
|---|---|---|
| New Input System 1.14.2 | PVE/PVP 均轮询 `MyInputSystem` | 改 `.inputactions`，不手改生成的 C#。 |
| Cinemachine 2.10.7 | PVE 双 FreeLook；PVP `PVPCameraRig` | 震动扩展在虚拟相机，切换时保持视角连续。 |
| Animation Rigging 1.2.1 | 荧/芙宁娜武器和瞄准 IK | Root Motion 保持启用；修改约束 data 后必要时 Clear/Build。 |
| AI Navigation 1.1.7 | PVE 敌人与随从 | NavMeshAgent 与 CC 不可争抢 Transform。 |
| URP 14.0.12 | 全局渲染 | MMD 材质有兼容 Shader；不能直接换回 Built-in Shader。 |
| TextMeshPro | PVE/PVP 动态 UI | 中文字体使用自有字体/Wizard，避免默认字形缺失。 |

### 必须保留的行为契约

1. **斜坡保护**：PVE 起跳 `SphereCast` 与落地 `cc.isGrounded` 的不对称是有意的；5 帧稳定窗口内贴地速度锁定，不要退化为单纯 `!isGrounded`。
2. **PVE 随从**：非主控角色的 `NavMeshAgent` 独占位移；`PlayerStateBase.Update()` 中不能因为非主控提前 `return` 而跳过随从分支。
3. **PVE 开火**：`PlayerWeapon` 0.15 秒限速，投射物防穿透并回池；PVP 只是复用其视觉，伤害依旧由服务端判定。
4. **PVP 协议**：JSON DTO 的两端字段、大小写、事件语义必须同步。可靠事件是死亡/重生/击杀/结束，常规快照是全量且不可靠。
5. **动画参数**：PVE/PVP 共用 `TPS_Movement.controller` 的角色要保持 `Speed`、`VerticalSpeed`、`IsGrounded`、`IsSprinting`、`AimingX/Y` 参数语义一致；Hunter 专用 `Hunter_Parkour.controller` 不能按该假设硬套。

## 5. 当前功能状态、风险与技术债

### 已有代码闭环（待运行验证）

- PVE：三角色切换、随从跟随、移动/冲刺/跳跃/滑铲、瞄准、荧/芙宁娜射击、敌人寻路/攻击/受击/死亡、血条、Game Over、主菜单。
- PVP：大厅连接、UDP 握手、输入上报、全量快照、本地预测/校正、远端插值、服务端命中与滞后补偿、死亡/重生/计分可靠事件、可选 bot。
- 工具：PVP 场景搭建、NavMesh 修复与诊断、场景物体吸附/障碍、CJK 字体、武器音频、血特效调整等 Editor Wizard。

### 明确未完成或高风险项

| 优先级 | 项目 | 事实与处理建议 |
|---|---|---|
| 高 | PVE/PVP 移动数值双写 | PVP 客户端与服务端分别维护常量；每次改动必须联调并考虑抽取共享定义的可行性。 |
| 高 | 文档时效 | `CLAUDE.md` 的 PVE 场景名和 PVP 30Hz 已过时；以本文件与当前源码核验。 |
| 中 | PlayerController 职责过重 | 输入、相机、IK、角色切换与死亡接管强耦合；拆分前先加回归验证，不做无目标的大重构。 |
| 中 | PVE 角色受击/死亡动画 | `hitAnimationName`/`deadAnimationName` 默认空，现阶段主要靠血量和日志兜底。 |
| 中 | 通用音频与 HUD | 有 `WeaponAudio`，但尚不是完整音频系统；弹药、准星、暂停、伤害数字仍没有完整主 HUD。 |
| 中 | PVP 场景碰撞 | 服务端移动没有墙体碰撞，掩体仅表现；若要做竞技公平性，需先设计权威碰撞方案。 |
| 低 | FPS 实验模块 | `FPSAimState` 仍留武器接入 TODO；不要误认为其已是 PVE 武器替代。 |
