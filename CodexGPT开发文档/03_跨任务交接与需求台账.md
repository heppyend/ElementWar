# ElementWar 跨任务交接与需求台账

> **目的**：在新的 Codex 任务、上下文压缩或多人接手时，提供唯一的可更新交接入口。它不替代源码、运行结果或 `AGENTS.md`，而是记录“当前要做什么、为什么这样做、做到哪里、还缺什么证据”。
>
> **强制阅读顺序**：`00_开发总纲与变更约束.md` → `01_项目基线与结构解析.md` → `02_当前问题与风险台账.md` → **本文件** → 目标模块 `AGENTS.md` → 相关源码。
>
> **维护规则**：每次任务开始更新“活动任务”；每次交付更新“当前快照”和活动任务状态；需求/决策历史只追加。没有源码、测试、运行截图、Console 输出或用户 GUI 证据的结论必须标为“待验证”。

## 6. 更新判定规则

- **需求改变**：新增一条第 3 节记录；若覆盖旧决定，标注被替代条目与原因，旧记录保留。
- **事实改变**：先以源码、构建、运行或 GUI 证据复核，再更新 `01`、`02` 或本文件的当前快照；不能把推测写成事实。
- **风险变化**：只在 `02` 的关闭标准有证据时才关闭或降级；在第 4 节同步留下验证证据。
- **用户完成 GUI 操作**：记录其声明，但仍根据风险要求 Inspector、Hierarchy、Console、运行截图或可读取配置等证据；证据不足时写“待验证”。
- **任务中断/上下文耗尽**：不猜测后续意图；更新第 2 节的当前状态、最后已完成步骤、未完成项和安全的下一步，再由新任务接手。
